# Mockup Library — The Studio Mode gallery

**Status:** v0.1
**Why it exists:** Founder direction — *"Studio Mode kde můžu vidět všechny mockupy, přidávat, upravovat a podobně"*. The Mockup Library is the visual brain of Studio Mode.

---

## What is a "mockup" in Vibell?

In Vibell, a **mockup** is any **rendered visual representation of a section, page, or full project** that exists outside of (or alongside) the live preview. Mockups are not code — they are visual artifacts that drive what the user wants the app to look like.

### Sources of mockups
1. **Wizard variants** — the 3 layouts shown in Step 3 of the wizard
2. **Variant Agent results** — the 3 options when user clicks "Show me 3 options"
3. **User-uploaded references** — screenshots, Figma exports, Pinterest pins (drag-drop into library)
4. **AI-generated explorations** — "show me 5 ideas for the hero section"
5. **Pinned snapshots** — versions of the live project the user wants to preserve

### What a mockup contains
- A **rendered image** (PNG screenshot of the live state at the time of capture)
- The **file map** that produced it (or a link to the snapshot)
- **Tags** (section, page, mood, color palette extracted automatically)
- **Notes** (user-written, AI-suggested)

## UI — The Mockup Library panel

Studio Mode workspace gets a **4th column** that can slide out (or be a fullscreen overlay):

```
[ Sidebar | Preview | Coach | Mockup Library ]
                                ▲
                                │ icon button in top bar
                                │
                          opens drawer / fullscreen
```

### Default view: Grid
- Tile grid of all mockups for this project
- Filter chips: All · Wizard · Variants · Uploads · Explorations · Pinned
- Sort: Recent · Most-clicked · By section
- Each tile:
  - Thumbnail (~200×140 px screenshot)
  - Title (auto-generated, editable)
  - Source badge ("Variant", "Upload", …)
  - Hover actions: Compare · Apply · Pin · Delete

### Detail view (click a mockup)
- Large preview with pan/zoom
- Right rail: metadata, tags, notes
- Actions:
  - **Apply to project** — replaces the live state (creates snapshot first)
  - **Use as inspiration** — sends the mockup as visual context to UI Editor for the next change
  - **Compare** — opens 2-up diff with another mockup or current live state
  - **Edit** — opens manual editor (see below)
  - **Generate variants from this** — calls Variant Agent with this as seed
  - **Export** — PNG / JSON
  - **Delete**

### Add mockup (button top-right)
Three options:
1. **Generate** — text/voice prompt → AI explores ideas → tiles arrive in library
2. **Upload reference** — drag/drop or file picker; AI extracts palette, tags it
3. **Capture current state** — screenshot the live preview right now and pin it

## Manual mockup editing

For users who want to tweak a mockup before applying it (without regenerating):

- **Inline editor opens in a modal or new pane**
- Click any element on the mockup → pop-up with edit options:
  - Change text (typed)
  - Swap component for another from a small palette
  - Adjust spacing / size with sliders
  - Replace icon (Lucide picker)
- Save → updated mockup tile in library; doesn't touch the live project until "Apply"

This is a **lighter version** of the workspace's click-to-edit, scoped to the mockup. It uses the same `data-vibe-id` infrastructure.

### What manual editing CANNOT do
- Add new sections (that's a Studio Mode generation action)
- Change layout structure (use "Generate variants from this" instead)

This keeps the manual editor simple. Want power? Use "Apply to project" then continue in the workspace.

## Compare mode

A signature feature for designers:

```
┌────────────────────┬────────────────────┐
│   Mockup A         │   Mockup B         │
│                    │                    │
│   [render]         │   [render]         │
│                    │                    │
│   Notes:           │   Notes:           │
│   "Cleaner type"   │   "Better hero"    │
└────────────────────┴────────────────────┘

       [ Pick A ]   [ Pick B ]   [ Merge: take A's hero, B's pricing ]
```

- 2-up side-by-side at any zoom level
- Synchronized scroll
- Click a section in either to start a directed change ("merge: take A's section X")
- "Merge" triggers a **Studio Agent** call that produces a new mockup combining the picked parts

Cost: 5 credits (it's a layout-level Studio operation).

## Storage

### Image storage
- Supabase Storage bucket `mockups/`
- Path: `mockups/<user_id>/<project_id>/<mockup_id>.png`
- Generated by `puppeteer` or `playwright` headless screenshot of the live preview
- Lazy: screenshot only on first save or after N seconds of stability

### DB

```sql
create table public.mockups (
  id          uuid primary key default gen_random_uuid(),
  project_id  uuid not null references public.projects on delete cascade,
  user_id     uuid not null references auth.users on delete cascade,
  source      text not null,            -- 'wizard' | 'variant' | 'upload' | 'exploration' | 'pinned'
  title       text not null,
  notes       text,
  tags        text[] not null default '{}',
  palette     text[] not null default '{}',  -- extracted hex colors
  thumbnail_url text,                     -- Supabase Storage URL
  full_url    text,
  snapshot_id uuid references public.project_snapshots(id), -- if it ties to a real state
  reference_url text,                     -- if uploaded, original source if known
  is_pinned   boolean not null default false,
  created_at  timestamptz not null default now()
);
alter table public.mockups enable row level security;
create policy "mockups read own"  on public.mockups for select using (auth.uid() = user_id);
create policy "mockups write own" on public.mockups for all using (auth.uid() = user_id);
create index mockups_project_idx on public.mockups (project_id, created_at desc);
```

### Limits
- Free plan: 5 mockups per project
- Basic: 25
- Standard+: unlimited
- Storage cost is small (~50–200 KB per mockup screenshot)

## Mockup Library × Memory Agent

When the user picks one mockup over another (or modifies one), the **Memory Agent** observes:
- Picked tile → preference signal ("user picked the version with violet hero gradient")
- Edited tile → preference + style ("user changed font to Geist 600")
- Uploaded reference → strong signal ("user references this layout style")

The result: future mockup generations **start closer to what the user actually wants**.

---

## Mockup Library × Marketplace (phase 2+)

Creators can publish their best mockups as **public mockups** to the Marketplace:
- Other users browse them like Pinterest for app layouts
- Click "Use this as a starting point" → the mockup becomes a generation seed in their wizard
- Original creator gets credit + small revenue share if the resulting app is paid

This turns Vibell into a **visual social network for app design**, not just code.
